# Принцип работы скрипта ozon_returns_fashion.gs

## Общая логика

Скрипт выгружает возвраты из Ozon через API и записывает их в Google Sheets.

### Шаг 1 — Получение данных из API

Функция `fetch_ozon_returns()` делает POST-запросы к Ozon Seller API с пагинацией по `last_id`. Каждый запрос возвращает до 500 записей. Цикл продолжается, пока в ответе `has_next === true`.

Период: последние **12 дней** (задано жёстко в `getDateRange()`).

Авторизация: заголовки `Client-Id` и `Api-Key`, которые читаются из листа «Настройка» (ячейки B2 и A2) через функцию `get_setting()`.

### Шаг 2 — Фильтрация

Фильтра по статусу нет — в таблицу попадают все возвраты. В данных встречаются два типа записей:

| Тип (`schema`) | Описание |
|---|---|
| `ReceivedBySeller` | Возврат уже получен продавцом, есть дата выдачи (`received_at`) |
| `ArrivedAtReturnPlace` | Товар в ПВЗ, дата выдачи ещё не сформирована |

### Шаг 3 — Сравнение с таблицей

Уникальный ключ строки: **`posting_number`** (колонка B, не A).

Колонка A (`Дата добавления`) — это дата запуска скрипта в момент вставки строки. При сравнении изменений эта колонка исключается, так как она не является данными из API.

Для каждой записи из API выполняется одно из трёх действий:

| Ситуация | Действие | Цвет строки |
|---|---|---|
| `posting_number` не найден в таблице | Добавить в конец таблицы | Серый `#efefef` |
| `posting_number` есть, поля не изменились | Пропустить | Без изменений |
| `posting_number` есть, поля изменились | Перезаписать строку (кроме кол. A), записать в лог | Жёлтый `#fff2cc` |

> **Примечание:** колонка A (`Дата добавления`) при обновлении строки не перезаписывается — она фиксирует момент первичного появления записи.

Поля, которые могут измениться:
- Колонка F: `visual.status_name` — статус возврата (например, `ArrivedAtReturnPlace` → `ReceivedBySeller`)
- Колонка I: `received_at` — дата выдачи (появляется только после перехода в `ReceivedBySeller`)

### Шаг 4 — Запись

- Новые строки дозаписываются в конец через `sheet.getRange(startRow, 1, rows.length, 12).setValues(rows)`.
- Изменившиеся строки перезаписываются точечно по номеру строки (кроме колонки A).
- Существующие неизменённые строки **не трогаются совсем** — ручная покраска пользователя сохраняется.

---

## Лог изменений

При обнаружении изменённых полей в лист «Лог» добавляется запись вида:

```
[Ozon] Обновлена запись posting_number=12345678-0001: Статус: "[ArrivedAtReturnPlace] Принят в ПВЗ" → "[ReceivedBySeller] Получен продавцом"
```

Итоговая строка лога по каждому запуску:

```
[Ozon] Добавлено новых: 5, обновлено: 2
```

---

## Цветовая схема

| Цвет | Значение |
|---|---|
| Серый `#efefef` | Новая запись, только что добавлена скриптом |
| Жёлтый `#fff2cc` | Существующая запись — статус или дата выдачи изменились по данным API |
| Без заливки / ручной цвет | Запись без изменений, цвет задан пользователем вручную |

---

## Конфигурация

Ключи API хранятся не в коде, а в листе «Настройка»:

| Ячейка | Значение |
|---|---|
| A2 | Api-Key (ключ продавца Ozon) |
| B2 | Client-Id (числовой ID кабинета) |

Состав колонок (12 штук, A–L):
`Дата добавления`, `posting_number`, `barcode`, `clearing_id`, `offer_id (артикул)`, `Статус`, `Причина возврата`, `Дата возврата`, `Дата выдачи`, `Количество`, `Цена`, `Вскрытая упаковка`.
