### Данные из API (первый успешный вызов)
- **Период запроса:** 30 дней
- **HTTP-статус:** 200 (впоследствии — 429, Rate Limit)
- **Всего записей в API:** 102
- **Записи со статусом "Выдано":** 76
- **Новых srid (отсутствуют в GS):** 26

### Данные из XLSX (выгрузка из кабинета WB)
- **Файл:** `wb_returns_report_marketplace.xlsx`
- **Строк данных:** 565
- **Строк в GS CSV:** 119
- **Расхождение:** **446 строк** — исторические данные, которых нет в Google Sheets

### Причина отставания
GS-скрипт `wb_returns_fashion.gs` при получении ошибки `429 Rate Limit` от WB API возвращает пустой массив (`return []`) и **молча прекращает работу**. Данные не записываются, триггер не сигнализирует об ошибке.

```
API → 429 Too Many Requests
         ↓
getWbData() → return []
         ↓
fetchWbReturns() → "Нет данных", выход
         ↓
GSheet не обновляется ← корень проблемы
```

### Требуемые действия
1. Добавить обработку 429 с повтором через 60 сек в `getWbData()` (файл `wb_returns_fashion.gs`)
2. Выполнить одноразовый бэкфил 446 строк из XLSX в Google Sheets
3. Убедиться, что триггер запускается корректно после исправления

## Debug-логирование в GS-скриптах (добавлено 2026-06-23)

Все три `.gs` файла дополнены логикой отладки. Логика данных не изменена.

### Что добавлено в каждый скрипт

#### WB — `wb_returns_fashion.gs`

**В `getWbData()`:**
- `[WB API] HTTP <код> | URL: <url>` — логируется при каждом запросе (200 и ошибки)
- `[WB API] Получено записей: N` — суммарное число записей в ответе до фильтра

**Новая функция `logWbDebugStats(data)` вызывается после `getWbData()`, до фильтра:**
```
[WB DEBUG] Всего записей из API: N
[WB DEBUG] Распределение по статусам:
  Выдано: N
  Принято в сортировочный центр: N
  ...
[WB DEBUG] Записей «Выдано»: N
[WB DEBUG] Агрегация «Выдано» по датам (K дат):
  2026-06-20: 3
  2026-06-21: 7
  ...
[WB DEBUG] Вчера (2026-06-22) «Выдано»: 7
```

### Как читать логи в Apps Script

1. Открыть GSheet → Расширения → Apps Script
2. Запустить нужную функцию (`fetchWbReturns` / `fetchYmReturns` / `Ozon_return_all`)
3. После выполнения: Просмотр → Журналы (Ctrl+Enter) — увидеть все `[WB/YM/Ozon DEBUG]` строки
4. Или: Выполнение → последний запуск → Журналы

### Что показывает "за день до" (вчерашняя строка)

Каждая функция логирует количество записей с нужным статусом за **вчерашнюю дату** отдельной строкой. Это ключевой индикатор для триггера, который запускается ежедневно: если вчера `= 0` — триггер либо не сработал, либо API не вернул данные.
